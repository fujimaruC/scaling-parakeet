# 10 — API CONTRACTS AND SYNC ENVELOPES

**Status:** normative v0.1 contract proposal. Route names can change by ADR but semantics and security constraints cannot. Prefix protected API endpoints with `/api/v1`. All payloads UTF-8 JSON unless specified; server responds with `application/json`, stable request ID and sanitized structured errors.

## 1. Authentication scopes
- `owner`: read/write tasks, candidates, settings, imports, notifications, exports and delete.
- `collector`: **write-only** to the allowed `sync` endpoint, with scoped credential, timestamp/nonce/replay protection. No access to `/tasks` or `/settings`.
- `scheduler`: internal Workers scheduled handler; **never** a public unprotected URL.
- `public`: static non-sensitive assets only. No private app state embedded in build artifacts.

Authentication failure `401` or `403`, no anonymous fallback. If Cloudflare Access handles login, Worker must trust only a verified assertion, not a client-supplied arbitrary header. Browser-changing requests require CSRF checks when cookies are used.

## 2. Endpoints

| Method | Path | Scope | Purpose |
|---|---|---|---|
| GET | `/api/v1/me` | owner | Identity and preferences (non-secret) |
| GET | `/api/v1/tasks` | owner | Paginated filtered tasks, `cursor`, `limit<=100` |
| POST | `/api/v1/tasks` | owner | Manual task creation |
| GET | `/api/v1/tasks/:id` | owner | Task + evidence/source assertions |
| PATCH | `/api/v1/tasks/:id` | owner | Versioned edit, `If-Match` required |
| DELETE | `/api/v1/tasks/:id` | owner | Soft delete with audit/tombstone |
| GET | `/api/v1/candidates` | owner | Review inbox and conflicting claims |
| POST | `/api/v1/candidates/:id/review` | owner | Accept/edit/dismiss/clarify (idempotent) |
| GET | `/api/v1/sources` | owner | Source configuration, health and coverage |
| GET | `/api/v1/recaps` | owner | Minimized approved recaps per source/import |
| POST | `/api/v1/sync` | collector | Signed ingestion envelope only |
| GET | `/api/v1/reminders` | owner | Upcoming/due/history and delivery status |
| PATCH | `/api/v1/settings/reminders` | owner | Owner notification rules |
| POST | `/api/v1/push/subscriptions` | owner | Register browser push subscription, opt-in |
| DELETE | `/api/v1/push/subscriptions/:id` | owner | Revoke device subscription |
| GET | `/api/v1/export` | owner | Authenticated versioned JSON export |
| POST | `/api/v1/sources/:id/purge` | owner | Delete one source and derived artifacts under owner-defined policy |
| GET | `/api/v1/health` | owner | Sanitized cloud/connector status |

Do not implement `POST /api/v1/cron/run` as public production API. For development, use Worker local cron tooling only.

## 3. Response envelope
```json
{
  "data": {"id":"task_opaque", "title":"Finish report"},
  "meta": {"request_id":"req_...", "server_time":"2026-11-05T08:00:00Z"}
}
```

Errors:
```json
{
  "error": {
    "code":"VERSION_CONFLICT",
    "message":"Task changed since your last update",
    "retryable":false
  },
  "meta":{"request_id":"req_..."}
}
```

Enumerated common codes: `AUTH_REQUIRED`, `ACCESS_DENIED`, `INVALID_PAYLOAD`, `UNSUPPORTED_SOURCE`, `VERSION_CONFLICT`, `REPLAY_DETECTED`, `RATE_LIMITED`, `DATA_SOURCE_STALE`, `QUOTA_EXHAUSTED`, `INTERNAL_ERROR`. Logs must not include raw input on `INVALID_PAYLOAD`.

## 4. Task creation example
```json
{
  "title": "Review database lecture",
  "course": "Database Systems",
  "due": {"precision":"date_only", "local_date":"2026-11-10", "local_datetime":null, "timezone":"Asia/Makassar"},
  "priority": "normal",
  "source_kind": "manual"
}
```
`due_at_utc` is nullable for date-only tasks; scheduled reminder *time* is separately generated by policy.

## 5. Collector sync envelope
See `../schemas/sync-envelope.schema.json`. Mandatory: `schema_version`, `batch_id`, `source_id`, `source_kind`, `client_generated_at`, `items` (bounded e.g. <=100), `coverage` with honesty label, `idempotency_key`. A source item may include minimal excerpt only if allowed, external opaque key, observed timestamp, SHA-256 content hash, derived candidate/claim objects validated separately. Never accept raw exported chat ZIP/file or model prompt as this endpoint's default body.

**Request auth example:** `X-Collector-Key-Id`, `X-Request-Timestamp`, `X-Nonce`, `X-Body-SHA256`, `X-Signature` over a canonical `(method,path,timestamp,nonce,body_sha256)` representation. Use carefully specified canonicalization, replay persistence and clock drift handling. Rotate credentials; never put signed data in URL query strings.

**Server behavior:** validate auth → size/schema/version → normalize IDs → transactional or carefully batched idempotent writes → return imported/skipped/conflicted counts and record IDs → update connector health. Client retries with **same** idempotency key on network uncertainty.

## 6. Candidate review example
`POST /api/v1/candidates/c_123/review`
```json
{
  "action":"accept_with_edits",
  "expected_candidate_version":2,
  "task_patch":{"title":"Submit lab report", "due":{"precision":"date_only","local_date":"2026-11-12","timezone":"Asia/Makassar"}},
  "idempotency_key":"client-generated-uuid"
}
```
Return linked canonical task, `task.version`, review event ID; follow-up status poll if network response lost. Reject approval when required evidence is missing or was purged, unless owner explicitly chooses `manual_override`.

## 7. Synchronization semantics
- `client_generated_at` is diagnostic, not trusted authority for access or order; server assigns `received_at`.
- Unique `(source_id, external_key)` is database-enforced. Import overlap returns `skipped_existing` not error.
- On timestamp/claim conflicts, save separate assertion; do not silently update authoritative task.
- Offline cache revision from server response uses opaque sequence/ETag. Don't assume local device clock is correct.
- Owner task update uses version match and audit; server responds 409 on stale write, not last-write-wins.
- Large import split into safe bounded batches; resume by persisted cursor and idempotency keys.
- Scheduled claims are protected by D1 state update; track ambiguous send as `unknown` to prevent dishonest delivered label.

## 8. Contract tests
- 401 anonymous task read, 403 collector task read, 403 user acting as collector, 409 stale task patch.
- 400 invalid precision/date (including nonexistent `2026-02-30`).
- 400 evidence ref outside batch.
- 409/422 duplicate idempotency key with changed body.
- 200 repeated identical envelope with unchanged row count.
- 413 oversize payload; 429 rate throttling.
- No data leak in error or telemetry body.
